## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/eva02_classification_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 3-file SHA-256 manifest inline (348 MB total) and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the module's last commit, its SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (timm instantiates its built-in `eva02_base_patch14_448` architecture and executes no remote model code). The notebook's only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/eva02_classification_input_manifest.json` with the schema, ceilings, per-input observations, verdict, and one recorded rejection finding; `evaluation_report` (EVAL21) writes `outputs/eva02_classification_evaluation_report.json` — `not-measurable` on the synthetic sample (with what labelled data would make the task measurable), `sample-sanity` with `top_k_accuracy` at k=1/k=5 when a ground-truth index is supplied.
- The default sample is a synthetic 320×240 RGB gradient generated in code — deliberately non-square so the squash to 448×448 is visible in the printed aspect ratio — with no download and no ground truth; its prediction is sanity evidence for the input contract and forward pass, not a correctness or benchmark claim. Every input is squash-resized to exactly 448×448 (`crop_mode: "squash"`, `crop_pct: 1.0`), so a non-square image is distorted rather than cropped.
- Classification obligations (Notebook Specification §20.1): the class count (1000) is printed before the model runs, the decision rule is `argmax`, softmax scores are described as uncalibrated (no threshold is shipped; downstream calibration is the caller's), and exported top-k scores keep their rank ordering in both JSON and CSV.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- **Runtime (RUN1, RUN10, ENV6):** nothing is installed into the notebook kernel. Section 1 downloads the pinned `uv` 0.12.15 wheel (refused unless its size and SHA-256 match), creates a managed CPython 3.12.12 environment and installs the carried hash-locked `tutorials/requirements-colab.lock.txt` (compiled from the `pyproject.toml` pins for manylinux x86_64) with `--require-hashes --only-binary :all:`; every later cell runs in one persistent worker in that environment. The notebook therefore supports **Linux x86_64 runtimes only**.
- **Fine-tuning (FT3–FT6, OUT8, OUT9):** The notebook default `TRAINABLE = 'head'` calls `fit(train_backbone=False)`: the pretrained backbone is frozen and only the new classifier (1,538 parameters) trains. `TRAINABLE = 'all'` (`train_backbone=True`, the package API's default) is full fine-tuning, which the Section 12 activity runs and shows drifting towards one class with these settings (30/40 in the local CPU check, every error a frog called a truck; head-only 38/40). The trainable and frozen counts are printed before training and checked against what `fit` trained; epochs, batch size, learning rate, weight decay, seed, method, counts and the dataset provenance (source, SHA-256, classes, split) go into `model-config.json` (`fine_tuning`) and `outputs/eva02_classification_result.json` (`fine_tuning.config`). `fit` seeds Python's `random` as well as PyTorch, so a CPU run repeats exactly.
- **Held-out evaluation (EVAL3, EVAL5, EVAL6, DAT8):** `finetune_evaluation_report` reports `n`, the count, the accuracy with its 95 % Wilson interval, the majority baseline, per-class counts and misclassified images; its verdict is `sample-sanity` and `comparison_to_baseline` is `above-baseline` only when the whole interval lies above the baseline. The default split is pair-grouped (a photo's original and darkened copies never straddle train and held-out) and the data cell compares every held-out image with the training images by pixel digest, stopping the tutorial path on any exact copy (SPL3; a BYOD archive gets a warning) and holds out 40 images (20 photos); the result is labelled a tutorial metric, not a benchmark, and the notebook says the interval is too narrow because the copies are correlated.
- **Dataset intake (DAT12, DAT13, DAT19, VAL1, VAL2, VAL7):** `load_image_zip` validates the archive before training — class-folder layout, val classes present in `train/`, at least 2 images per class and 2 classes, every image decoded and checked against `MAX_IMAGE_SIDE`, archive limits — and names the file or class it refuses; the air-gapped fallback (`synthetic_stripes_dataset`) runs end to end.
- **Reload (VER4, VER5, REL7):** the reloaded artifact is compared with the in-memory model on every held-out image (labels and a 1e-4 score tolerance) and the artifact's SHA-256 digests are recorded.
