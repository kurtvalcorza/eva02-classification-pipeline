## Conformance notes

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/eva02_classification_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 3-file SHA-256 manifest inline (348 MB total) and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the module's last commit, its SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (timm instantiates its built-in `eva02_base_patch14_448` architecture and executes no remote model code). The notebook's only external dependencies are the pinned PyPI distributions and the Hub at that revision.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/eva02_classification_input_manifest.json` with the schema, ceilings, per-input observations, verdict, and one recorded rejection finding; `evaluation_report` (EVAL21) writes `outputs/eva02_classification_evaluation_report.json` — `not-measurable` on the synthetic sample (with what labelled data would make the task measurable), `sample-sanity` with `top_k_accuracy` at k=1/k=5 when a ground-truth index is supplied.
- The default sample is a synthetic 320×240 RGB gradient generated in code — deliberately non-square so the squash to 448×448 is visible in the printed aspect ratio — with no download and no ground truth; its prediction is sanity evidence for the input contract and forward pass, not a correctness or benchmark claim. Every input is squash-resized to exactly 448×448 (`crop_mode: "squash"`, `crop_pct: 1.0`), so a non-square image is distorted rather than cropped.
- Classification obligations (Notebook Specification §20.1): the class count (1000) is printed before the model runs, the decision rule is `argmax`, softmax scores are described as uncalibrated (no threshold is shipped; downstream calibration is the caller's), and exported top-k scores keep their rank ordering in both JSON and CSV.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
